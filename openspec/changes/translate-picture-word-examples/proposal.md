# Make lexical examples consistent across card workflows

## Why
A picture adjective can show an untranslated anchor while noun cards use a separate bilingual preparation path. Other routes also treat examples differently: the verb example review receives German but not Russian, and some sentence workflows can retain an old translation when enrichment changes the German text. Multiple representations and duplicated handoffs make the same learner-facing example hard to validate consistently.

## Approaches
1. Translate adjective anchors only: a narrow repair that leaves the other example inconsistencies and duplicated handoffs in place.
2. Introduce one shared example contract and lifecycle, retaining purpose-specific validation policies: recommended. A validated German/Russian pair becomes the source for preview and card fields across lexical and verb workflows.
3. Force all cards through one identical prompt, sentence shape and validator: superficially uniform, but loses verb morphology, lexical-cloze uniqueness, imageable phrases, and sentence-card requirements.

## Design
Represent each learning example as a single structured pair: German text, Russian translation, target surface form, target lemma, selected sense and example kind (phrase or sentence), plus optional image context. Use shared construction, structural checks, review handoff, bounded repair, and preview-to-save mapping. Do not duplicate the example and its translation into independently mutable values. The shared validation entry point MUST ensure both texts are nonempty, the target appears as required by the active policy, and a semantic review checks that the translation expresses the German example and chosen sense. User-entered examples and edited or regenerated pairs follow the same contract. If German changes, never retain its prior translation without a new matching translation and review. Do not silently replace an explicitly selected example or sense; show the updated pair and require normal confirmation.

The user-approved architecture requires one coordinator to own the common lifecycle; differences are separate functions or modules supplied as policies. Validation is compositional: picture adjectives can use short natural phrases; nouns can use sentences; sentence/audio cards require suitable sentences; lexical cloze retains exact target and uniqueness/synonym handling; verb forms retain person, inflection, separable-verb identity and selected-sense checks. Existing focused checks become policies invoked through the shared lifecycle, not replaced by a generic lexical-identity test. Integrate existing AI review in that lifecycle where possible; do not blindly add an extra model request for every screen or candidate. Candidate lists must contain a German example and Russian translation; the finally selected pair is validated for the chosen sense before final preview. Once a validated pair is confirmed, card construction and audio generation consume the same pair; a later mutation invalidates the prior review.

On validation or translation failure, use bounded repair carrying the feedback, then offer an explicit retry, edit, skip, or safe alternate route as appropriate; never silently show an untranslated example, substitute a generic word gloss for a sentence translation, save an unreviewed pair, or discard an already confirmed independent card. Retain existing user choices, Anki duplicate/recovery guarantees, English interface and Russian learning text. New behavior applies to newly created cards across nouns, adjectives, adverbs, function words, verbs, inflected forms, and cloze/sentence/picture routes. Existing cards are not automatically migrated; the specific `fest` note repair is handled only when explicitly authorized.

## Result for the reported card
The phrase `feste Schraube` remains a phrase and is paired with `прочно закреплённый винт` in both preview and saved card. The same contract applies when the example is a full sentence or the target is a verb form, without erasing the grammar-specific checks.
